# pupikes-doctor — Reviewer note (Huawei AppGallery)
Version 1.0023

## For reviewer
This version adds on-device neural photo recognition. It builds on 1.0022 (reply to rule 3.1: "the analysis results are the same regardless of which problem is selected / which photo is taken" — the reference library now loads in parts after the first screen, every skipped step is reported, advice is built in offline, three sample cases show the whole flow).

What is new in 1.0023:
- The photo is examined by a neural network that runs entirely on the phone: MobileNetV3-Small (TensorFlow.js, about 3 MB, bundled in the APK — no download, no internet, nothing is uploaded). It turns the photo into a numeric fingerprint and compares it with a library of reference images that was pre-computed at build time (the previous fingerprint corpus plus 100+ checked photos for each of the 25 conditions the app knows). The result is the three most similar conditions with percentages, e.g. "Photo (neural model) — looks like: Sunburn (62 %), Rash (21 %), Burn (9 %)".
- The photo is a second opinion. The questionnaire (body area, type of pain, when it hurts, pain level, size, free-text complaint) remains the main input; the photo percentages only add points to the matching conditions and are listed after the questionnaire result. A different photo therefore gives a different "looks like" line and a different order.
- Honest fallback: on a phone with 1 GB of memory or less, or if the model cannot be loaded (missing file, WebGL/memory error, timeout), a line under the photo button says "Neural model: unavailable (reason) — the older fingerprint comparison is used", and the analysis still runs the 1.0022 way. Nothing fails silently.
- Status line under "Photograph the problem": "Neural model: loading (n of m)…" → "Neural model: ready (18,498 images in the library, runs on the device)".
- "More about this": every result card ends with links in the interface language that open in the system browser — Wikipedia in that language (direct article where the built-in pack knows the title, otherwise a search) and in English, MedlinePlus (NIH; Spanish edition for Spanish), NHS, and MSD Manuals consumer edition for ru/uk/de/fr/es/it/pt/ar/hi/ja/zh (plus gesund.bund.de for German). Nothing is downloaded; the app carries no description databases. The built-in short data (description, what to do, when to see a doctor) for the 25 common conditions stays as before.
- Optional setting "Connect to the Pupikes server: improve recognition" (a card at the bottom of the Symptoms / photo tab, OFF by default, explained on screen): when on, the app fetches new numeric fingerprints from our server once per launch and merges them into the on-phone library, and each result card gets a button "✓ This was it — <condition>" that sends ONLY the numeric fingerprint of the photo (1024 numbers computed on the device) and the chosen condition — never the photo itself, no name, no location, no account. The "More about this" section may also receive a short summary in the interface language from the server. With the setting off nothing is ever sent.
- All new texts are in the 15 interface languages.

How to test:
1. Launch the app → choose a language → accept the medical disclaimer → the home screen opens immediately.
2. Under the button "Photograph the problem" two status lines appear within a few seconds: "Photo library: ready (16,778 reference images)" and "Neural model: ready (… images in the library, runs on the device)". On a first launch the model line may take 5–15 s (shader compilation); the app is usable meanwhile.
3. Tab "Symptoms / photo" → card "Sample cases" → tap "Scraped knee". Expected: the photo of a scraped knee appears, the form is filled, and within a few seconds "Possible matches" starts with a line "Photo (neural model) — looks like: Abrasion / graze (…%), …" followed by "The photo is a second opinion — the area, pain and complaints lead." and the cards (Abrasion / graze first).
4. Tap "Sunburnt shoulders". Expected: a different photo, a different "looks like" line (Sunburn leads) and a different card order. Tap "Scaly plaque on the elbow": Psoriasis leads.
5. Own photo: "Photograph the problem" → take/choose any photo → Analyze. Expected: the status shows "The neural model is examining the photo…" for 1–4 s, then the result begins with "Photo (neural model) — looks like: …" (three conditions with percentages) or, if nothing in the library resembles it, "…the nearest images do not point to a listed condition — the symptoms lead." A photo that cannot be read gives "The photo could not be read … comparison skipped" and the symptom result still appears.
6. Own input without a photo: Area = Joint, Type of pain = Sharp, Pain frequency = On movement, Pain = Severe → Analyze. Expected: Sprain / Dislocation / Possible fracture. Change to Area = Skin, Type = Itching, frequency = At night → Analyze. Expected: Rash / Eczema / Hives / Fungal — a different list.
7. Airplane mode: repeat steps 3–6. Expected: everything works, including the neural model (it is bundled); on a non-English/Bulgarian phone the advice shows in English with the note "Translation unavailable (no connection)".
8. Tab "Where it hurts" → choose a figure → tap a body part (e.g. the knee). Expected: a card with possible causes, an emergency line where relevant, and a short encyclopedic paragraph in the chosen language.
9. In any result card, tap a link under "More about this" (e.g. "Wikipedia (English)" or "MedlinePlus"). Expected: the system browser opens the page; the app stays where it was.
10. Optional server setting: scroll to the bottom of the Symptoms / photo tab → the card "Connect to the Pupikes server: improve recognition" is OFF. Switch it on → run a sample case → each card now shows "✓ This was it — <condition>"; tap it → "Saved — thank you!" (or, without a connection, "Saved to the on-phone library; the server is unreachable — not sent"). Switch the setting off → the buttons disappear on the next analysis.

Everything is informative only (medical disclaimer on first launch and on every screen); no account, no login, no upload of the photo — both the neural model and the comparison run on the device. The optional server setting sends numeric fingerprints only and is off by default.
