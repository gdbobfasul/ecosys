# PupikesMetamaskCoinCreator

Бот, на който **ти избираш само детайлите**, а той прави **всичко сам**: има си собствен трезор (MetaMask акаунт),
пуска токени от меню, следи ги, прави статистики, **пази ги от кражба**, управлява цената (ликвидност/изгаряне/
изкупуване), продава по твоя команда и тегли парите към твой акаунт. Ти имаш достъп до същия акаунт → гледаш и
контролираш — ботът сам отваря **MetaMask в Edge** с трезора си, ти само наблюдаваш.

## Най-краткият път — АВТОПИЛОТ (ти само превеждаш BNB)
```
node bot.js autopilot <id> [bnbЗаЛиквидност] [--all] [--vault <адрес|№>] [--no-wallet]
```
1. Ботът отваря **Edge + MetaMask** с трезора си (отделен профил `wallet/mm-edge-<кратък адрес>/`; личният ти Edge
   НЕ се пипа). Първия път внася сийд фразата сам (парола → `wallet/mm-edge-<кратък адрес>.json`), после само отключва.
   Добавя мрежата от `config.activeNetwork`, внася пуснатите токени, добавя акаунт #1 (пазача) — в MetaMask виждаш
   **същите** акаунти като на бота (Account 1 = трезор, Account 2 = пазач).
2. Печата **„Преведи BNB на този адрес"** + мрежата. Ти превеждаш. Сумата за ликвидност: аргумент, или ботът пита
   в терминала (Enter = всичко над резерва за газ), или `--all`.
3. Проверява баланса на всеки 10 s; щом покрие газ + ликвидност + резерв (`market.gasReserveBnb`) → продължава.
4. `create` (деплой + Vault Guard + зареждане на пазача с газ + страница `https://pupikes.com/crypto/<slug>/`).
5. `liquidity` (PancakeSwap) с подадената сума и `market.liquidityTokenPercent` % от предлагането.
6. `stats` / `price` / `advise`, обновява страницата и индекса `/crypto/`, внася новия токен в MetaMask.
7. Остава в **`monitor`** (охрана). Дневник: `wallet/autopilot.log`. При грешка — честно съобщение и спиране,
   **без повторен деплой** (вече пуснат токен никога не се деплойва пак; ако има пазар — не добавя втори).

## Как работи (целият поток, стъпка по стъпка)
1. **Портфейлът на бота** — `node vault.js new` създава трезор (24-думна сийд фраза + парола, в `wallet/`).
   Регистър на всички трезори, които ботът някога е създал: `wallet/vaults.json` (`node vault.js list`) — включва и
   старите в `wallet-backup-*/`. Всяка команда приема `--vault <адрес|№>`; по подразбиране работи с текущия `wallet/`.
2. **Гледаш в MetaMask** — `node watch.js [адрес|№]` показва регистъра, избираш трезор → Edge + MetaMask с него.
   Непознат адрес (не е създаден от бота) → няма сийд → отказ с ясно съобщение.
3. **Избираш токен от менюто** — `node bot.js menu` (10 токена, всеки със своя специфичност) → `node bot.js create <id>`
   или направо `autopilot <id>`.
4. **Пускаш пазар** — `node bot.js liquidity <id> <bnb> <tokens>` (PancakeSwap) → токенът има цена.
5. **Ботът следи и пази** — `node bot.js monitor` авто-отменя подозрителни (кражби); `stats <id>` записва цената;
   `advise <id>` предлага легитимни ходове.
6. **Продаваш когато решиш** — `node bot.js sell <id> <tokens>` → `node bot.js withdraw <bnb> <твой-адрес>`.

## Менюто — 10 токена, всеки с уникалност
`node bot.js menu`. Всички работят нормално като ERC-20, но всеки има своя черта:
guard 🛡 (анти-кражба за всички), sentinel 🛡⏳ (наследяване), ember 🔥 (1% изгаряне), harvest 🏦 (2% фонд),
fair 🐋 (анти-кит), shield 🛡+🏦, nova ⚖ (балансиран), green 💚 (благотворителност), pulse 🔥+🛡, loyal 🎁, aegis 🏛.
Флагман near-unique черта = **🛡 Vault Guard**: голям превод се задържа и може да се отмени → откраднат ключ не източва.

## Команди
```
node vault.js new | show | list | exportkey   # трезор на бота; list = регистър на всички трезори
node watch.js [адрес|№]                       # ВИДИМО: Edge+MetaMask с избрания трезор (сийдът се внася сам)
node metamask.js open [адрес|№] | where       # същото на ниско ниво / къде е разширението и профилът
node bot.js autopilot <id> [bnb] [--all]      # ВСИЧКО само (виж горе)
node bot.js menu                              # каталог с 10-те токена
node bot.js create <id>                       # пуска избрания токен (+ Vault Guard + страница)
node bot.js list | status <id> | wallet       # пуснати / инфо / портфейл+баланс
node bot.js monitor [id]                      # ПАЗИ: авто-отменя кражби от трезора (пише wallet/monitor.pid)
node bot.js liquidity <id> [bnb] [tokens]     # пуска пазар (без суми → ботът ги попълва сам по config)
node bot.js price <id> | stats <id>           # цена / статистика във времето (× спрямо старта)
node bot.js advise <id>                       # съветник: легитимни ходове за качване на цената
node bot.js buy <id> <bnb>                    # [демо] купи (симулира търсене на testnet)
node bot.js sell <id> <tokens>                # продай токени → BNB (в бота)
node bot.js burn <id> <tokens>                # изгори от трезора (дефлация)
node bot.js withdraw <bnb> <адрес>            # тегли BNB към твой друг акаунт
node bot.js page <id> | index                 # (пре)генерира страницата на токена / индекса /crypto/
   --vault <адрес|№>                          # (към всяка команда) работи с избран трезор от регистъра
```
От старт менюто (`deploy-scripts/00-menu.sh`): точки **70–75** (MetaMask в Edge · автопилот · каталог/статус ·
пазар · охрана · портфейл/мрежа).

## Страницата на токена
`create`/`page` пишат `public/crypto/<slug>/index.html` → публично **`https://pupikes.com/crypto/<slug>/`** (след деплой
на сайта). Съдържа: адрес на договора, мрежа, символ, снабдяване, такси/лимити, Vault Guard, BscScan, PancakeSwap
(ако има пазар), **QR** на адреса, бутон **„Добави в MetaMask"** (EIP-747 `wallet_watchAsset`, превключва/добавя
мрежата сам), цена/ликвидност (обновяват се при `liquidity`/`stats`). `public/crypto/index.html` има блок
`<!-- BOT-TOKENS -->`, който ботът регенерира с всички токени от `deployments/` (`node bot.js index`).

## Мрежа
`config.json` → `activeNetwork` (`bscTestnet` за тест / `bscMainnet` за реално). `walletMode:"vault"` = ползва
портфейла на бота (`wallet/`). Всеки токен се записва в `deployments/<мрежа>-<id>.json`.
`market.gasReserveBnb` = резерв, който автопилотът винаги оставя; `market.minLiquidityBnb` = минимум при `--all`;
`protect.minGuardianGas`/`guardianGasTopUp` = газ за пазача (ботът го зарежда сам).

## MetaMask в Edge — как точно (MetaMask 13.47, проверено 11.09.2026)
Playwright пуска Edge (`channel: msedge`, резерва Chrome) с разширението от
`%LOCALAPPDATA%\Microsoft\Edge\User Data\<профил>\Extensions\nkbihfbeogaeaoehlefnkodbefgpgknn\<най-нова версия>`
и отделен профил `wallet/mm-edge-<кратък адрес>/`. Първо пускане: „I have an existing wallet" → „Import using Secret
Recovery Phrase" → фразата се въвежда в полето (само се разделя на 24 думи) → парола → Windows Hello „Maybe later" →
метрики изключени → „Open wallet". Мрежата и токените се добавят през стандартния портфейлен API
(`wallet_addEthereumChain`, `wallet_watchAsset`) от мост-страница на 127.0.0.1; ако MetaMask покаже прозорец за
потвърждение, ботът го натиска; ако не успее за 30 s — казва кой бутон да натиснеш. Непознат екран → снимка
`wallet/mm-screen.png` + указание. Забележка: раздел **Activity** на MetaMask показва само транзакциите, които
самият MetaMask е подписал/индексирал; действията на бота се виждат сигурно в **Tokens** (балансите) и в BscScan.

## Честно за „5×"
Ботът дава всички легитимни лостове (ликвидност, прозрачно изгаряне, изкупуване, статистики, съветник). Реалният
драстичен ръст обаче идва от **истинско търсене** (полезност, общност, листване), не от трик. Механизми за изкуствено
надуване на цената пред реални инвеститори са манипулация — не ги правим.

## V2 защити (от 11.09.2026, след MEV роботите по пула на HRVS)

Новите токени се пускат с `PupikesFeatureTokenV2` / `PupikesSentinelTokenV2` / `PupikesGuardTokenV2` (обща основа
`PupikesV2Base.sol`). Пуснатите преди това (HRVS `0x4275…5A5A`) остават на стария договор — по тях нищо не се мени.

Всяка мярка се включва и изключва по всяко време от собственика (0 = изключена), без нов договор:

| Мярка | По подразбиране | Команда |
|---|---|---|
| Блокиране на адреси | известните MEV роботи се блокират при create | `block` / `unblock` / `blocked` |
| Затворена търговия при пускане | 10 мин. след ликвидността | `open <id> [сек]` |
| Спиране на търговията | изключено | `pause` / `unpause` |
| Задържане на големи преводи | над 5 000 → 30 мин. | `set <id> large <праг> <сек> [прагЗамразяване]` |
| Замразяване до одобрение | над 10 000 (само локално и в админа; публично НЕ се обявява) | `approve` / `freeze` / `release` / `refund` |
| Един превод на адрес за 1 час | включено | `set <id> ratelimit <сек>` |
| Проверка на плащането при купуване (skim) | толеранс 3% | `set <id> buycheck <bps>` |
| Анти-снайпер | първите 2 блока | `set <id> sniper <блокове>` |
| Лимит на портфейл при пускане | 1% за 24 ч | `set <id> launchcap <bps> <сек>` |
| Една транзакция на блок | включено | `set <id> onetx on/off` |
| Whitelist (без задържане) | рутерът се добавя при create | `whitelist <id> add/remove <адрес…>` |
| Оператор (блокира/спира/замразява) | няма | `set <id> operator <адрес>` |
| Втори одобряващ (Tangem) + два подписа | няма | `set <id> approver <адрес>` · `set <id> twoapprovals on` |
| „Вторият командва“ | изключено | `set <id> secondcontrols on` (включва се с два подписа, изключва само вторият) |
| Възстановяване при откраднат ключ | срок 24 ч | `recover status/cancel` (останалото — от втория одобряващ) |
| Спасяване на заседнали средства | — | `rescue <id> bnb/<токен> <адрес>` |
| Заключване на LP | — | `locklp <id> <дни>` / `unlocklp <id>` |

Всичко това е и в старт менюто: **72** (четене: правила, задържани преводи, whitelist, блокирани, verify) и
**73** (действия, с потвърждение „да“ на mainnet).

Какво вижда публично страницата на токена: само едно правило — преводи и търговия над прага (5 000) изискват
одобрение от собственика и може да се задържат, плюс общото изречение за необичайната активност. Второто ниво
(замразяване) и точните стойности се виждат само в бота, в личните Telegram известия и в админ страницата
след вход със собственика.

⚠ Важно за потребителите: правилото „един превод на адрес“ отказва втора продажба в рамките на 1 час, а
PancakeSwap показва обща грешка (TransferHelper) — истинската причина се вижда само в договора. Голяма покупка
стига до купувача след одобрение; рутерите, които проверяват получената сума, отказват такава покупка.

## Пускане на НОВ токен с V2 (процедура)

1. Записът в каталога вече съществува: **harvest2** — „Pupikes Harvest“ (HRVS), `PupikesFeatureTokenV2`,
   отделен адрес на страницата `/crypto/pupikes-harvest-v2/`. Старият (мъртъв) HRVS пази `/crypto/pupikes-harvest/`
   и псевдонима `/crypto/hrvs/`; записът `deployments/bscMainnet-harvest.json` НЕ се пипа.
2. Провери правилата в `config.json`: `market.largeTransferThreshold` / `largeTransferDelaySec` /
   `freezeTransferThreshold` и `protect.*` (прозорец за честотата, толеранс, снайпер, лимит при пускане, една транзакция на блок).
3. `node bot.js create harvest2` — деплой, охрана на трезора, блокиране на известните роботи, рутерът в whitelist,
   правилата от config. Търговията остава ЗАТВОРЕНА.
4. `node bot.js liquidity harvest2 <bnb> <токени>` — ЕДНА транзакция (approve + addLiquidityETH със симулация и
   минимуми), после пазарната двойка в договора и `openTrading(600)`.
5. `node bot.js verify harvest2` — проверка на изходния код в BscScan.
6. По желание: `node bot.js locklp harvest2 <дни>`; `set harvest2 approver <адрес на Tangem>`;
   `set harvest2 twoapprovals on`; по-късно `set harvest2 secondcontrols on` (изключва се само от Tangem).
7. Наблюдение: `node bot.js monitor harvest2` (меню 74) — известия за задържани преводи в личния Telegram чат
   (`TELEGRAM_OWNER_CHAT_ID` в `.env`); по избор `watch dev on` и `guardauto on`.

## Сигурност
`wallet/` (сийд, ключове, keystore, MetaMask профили и пароли, регистър, дневници) е в `.gitignore`. На mainnet дръж
сийда офлайн: който го има, управлява акаунта. Таксите/лимитите на токените са **непроменяеми** след пускане (без
„rug"/honeypot); собственикът няма опасни правомощия. Автопилотът никога не деплойва повторно и никога не харчи под
резерва за газ.
