# scraper-bot — събирач на контакти (бекенд)

Разширена версия на десктоп скрипта `scrap1_sendmails.py` (оригиналът е запазен тук като
`original-scrap1_sendmails.py`; истинският му дом остава `C:\wrk\OpenDevin\eco3\` — НЕ е местен).
Тук е **бекенд услуга с API**, за да го управлява мобилното/уеб приложение по трите варианта:

1. **Търсене** — заявка (напр. „адвокат София") през **14 търсачки** (Google, Bing, DuckDuckGo,
   Yahoo, Ecosia, Startpage, Brave, Mojeek, Ask, Yep, Dogpile, Metacrawler, Swisscows, Gibiru).
2. **Какво събираме** — `collect`:
   - `emails` | `phones` | `both` — контакти (regex + чистене на боклук).
   - `content` — извлича ОСНОВНИЯ текст на статията (readability-lite), разпознава ТИПА
     (recipe/news/event/object/product) и връща `snippet` (изречението-доказателство).
   - `links` — само URL-та (за да строиш дърво в апа), с тип и score.
   За `content`/`links` се вадят и СТРУКТУРНИ полета: `title`, **`author`** (schema.org/byline
   „Автор:"), `date`, `source`(url), `snippet`, `text`.
3. **Обработка** — приложението решава:
   - показва JSON-а на екрана;
   - **сваля файл** — текст (`save:true`) или **Excel/CSV таблица** (`save:"csv"`; колони
     url,type,title,author,date,score,snippet,text — точно „url, пълен текст, автор");
   - **изпраща писма** до събраните имейли през `/send`; или **до СВОЯ имейл** (човекът праща
     резултатите на себе си — `/send` с неговия адрес + CSV като `attachment`).

## Многостепенно (nested) търсене
Стъпка 1: `/scrape` `collect:"links"` за „български рецепти" → URL-та. Стъпка 2: `/extract`
върху тези URL-та с филтър „мусака" и `collect:"content"` → вадиш **авторите**. Така автор
може да намери къде е публикуван. Всяка стъпка е отделна API заявка (веригата се управлява от
приложението).

## „Лека логика" — точност и тематика (без платен LLM)
Търсачките изпускат думи (пишеш „българска кухня майонеза зеленчуци", а излиза мексиканска).
Затова подаваш `filters` в `/scrape` и всяка сваляна страница минава през ГЕЙТ (`content.py`):
```
"filters": {
  "must_all": ["българ", "майонеза", "зеленчуци"],   // ВСИЧКИ да ги има (иначе отпада)
  "any_of":   ["рецепта", "салата"],                  // поне една
  "exclude":  ["мексикан", "реклама"],                // ако я има → отпада
  "focus":    ["пластмаса"],                           // целевата дума…
  "context":  ["конструкция", "материал", "стена"]     // …трябва да е В ЕДНО ИЗРЕЧЕНИЕ с контекст
}
```
Пример „производител на дървени къщи" + `focus:пластмаса` + `context:конструкция` +
`exclude:убийство,улика` → връща само описания, където пластмасата е КОНСТРУКТИВЕН елемент,
не където пластмасов предмет е улика по разследване. Връща и самото изречение (конкретика).
Тествано изолирано (`content.py`): рецепта се разпознава, мексиканската отпада; конструкция ✓, улика ✗.

## Файлове
- `extract.py` — извличане на имейли/телефони (без зависимости; тестван).
- `scraper.py` — обхождане на търсачките + събиране (Playwright, мързелив внос).
- `mailer.py` — SMTP изпращане с прикачен файл, журнал за изпратени, лимит/забавяне.
- `server.py` — HTTP JSON API (stdlib, без Flask).
- `config.py` — чете `.env` (без задължителен python-dotenv).

## Пускане (на машина с интернет и браузър)
```bash
pip install -r requirements.txt
python -m playwright install chromium
cp .env.example .env      # попълни SMTP + токен
python server.py          # API на порт 3030
```

## API
- `GET /health` → `{ok, playwright}`
- `POST /scrape` `{query, collect?, engines?, filters?, types?, max?, headless?, save?}`
  → `{ok, count, results:[…], file?}`  (save: true|"txt"|"csv")
- `POST /extract` `{urls:[…], collect?, filters?, types?, save?}` → същото, но върху ГОТОВ
  списък URL-та (стъпка 2 на многостепенно търсене — без ново търсене в търсачките)
- `POST /send` `{emails|items, subject, body, attachment?, delay?}`
  → `{ok, sent, skipped, errors}`

Ако `scraper_api_token` е зададен в `.env`, всяка заявка иска `Authorization: Bearer <token>`.

## Важни бележки / още за правене
- **CAPTCHA:** оригиналът спираше за РЪЧНО решаване (Enter). Тук по подразбиране е **headless
  и неинтерактивно** (за сървър) — търсачките, които блокират с капча, се прескачат; използват
  се тези, които връщат резултати. За по-висок улов трябва headful режим/решаване на капча.
- **Дълга заявка:** `/scrape` е синхронен. За продукция сложи **опашка от задачи** (job id +
  poll/stream на прогреса), защото обхождането трае минути.
- **Деплой:** като другите услуги в `private/` — systemd + nginx (`/api/scraper/`). Още НЕ е
  добавен деплой скрипт/меню.
- **Фронтенд в апа:** `pupikes-toolkit-scraper` още вика слабата локална версия — трябва да се
  пренапише да говори на това API (трите варианта). НЕ е направено още.
- Работи от машина с реален IP/браузър — не от телефона (телефонът само вика API-то).
