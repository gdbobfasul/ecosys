# Organizer-Bot

Подрежда файлове в подадени директории `A1, A2…` и ги изнася в главна директория `C`.
**ВСИЧКО го прави този бот** (не отделни скриптове). **Местенето е ПО ПОДРАЗБИРАНЕ** — файловете се
преместват в `C` и НЕ остават в старите папки (това е „триенето"). За само преглед без местене: `--dry-run`.

## Функции

### 1) `exact` — точни (идеални) дубликати
Намира байт-в-байт еднакви файлове (sha256). Групите се местят в `C/<Bдир>`, където името на
B-папката = **името на A-дир + поддиректориите до файла, разделени с тире** (напр. `A1-sub1-sub2`).
Файловете се преименуват на **най-дългото име** от групата + `-<N>`:
напр. `1.pdf`, `gsaga4eft.pdf`, `fddga-ddge4-4d.dg.pdf` → `fddga-ddge4-4d.dg-1.pdf`, `-2.pdf`, `-3.pdf`.

```
node private/organizer-bot/organizer-bot.cjs exact --dirs "G:/път/A1,G:/път/A2" --out "G:/път/C" [--dry-run]
```

### 2) `similar` — подобни файлове
Като (1), но за **подобни** (не идентични): текст/doc/pdf с ~90% съвпадение, намалено качество,
производен файл или добавено съдържание; картинки, едната производна/смалена на другата.
- **текст/pdf/docx/doc**: токен-прилика (Jaccard + „съдържание в" → хваща и производни), праг `--threshold` (0.82).
- **картинки** (png/jpg/jpeg/gif/webp/bmp): перцептуален dHash през Playwright (headless Chromium), Hamming ≤ `--img-dist` (10).
Имената: най-дългото + `-similar-<N>`.

```
node private/organizer-bot/organizer-bot.cjs similar --dirs "G:/път/A1" --out "G:/път/C" [--threshold 0.82] [--img-dist 10] [--dry-run]
```

### 3) `cases` — анализ на преписки/дела (НЕ мести; АКУМУЛИРА)
За всяка дир `A_i` проверява дали файловете са по **една преписка/тема** (`пр.пр. № NNNNN/ГГГГ` или
`дело № N/ГГГГ`). Мини-таблица на всяка папка: разпознати преписки/дела + доминираща; **кои файлове НЕ
са по преписката**; инстанции (СРП/СГП/ВКП/АП/МВР-СДВР/съд) + **„⚠ ЛИПСВА СГП/СРП"**.

**Акумулиращо кръстосване папка ↔ имейли:** логваш се РЪЧНО в един имейл наведнъж и подаваш `--email`.
Ботът извиква **Email-Bot** (`--case`) за всяка преписка/дело и **трупа находките през рунове** в ЕДИН
файл (`organizer-cases.md` + `.state.json`). Логваш се в следващ имейл → пускаш пак → добавя се нов
раздел; накрая знаеш за всички имейли кои преписки/дела къде ги има. Записва **пълното „относно", дата/час,
акаунт**. Разграничава:
- **прокурорски преписки** → извод за СРП/СГП: „НЕ е в папката, но ИМА в имейл X → не е свалена".
- **съдебни дела** → гледа **прикачените МОЛБИ/документи** в писмата: кои ги няма на диска и може да се свалят.

```
# първо само папките:
node private/organizer-bot/organizer-bot.cjs cases --dirs "G:/път/DELO1,G:/път/DELO2" --out "G:/път/C"
# после за всеки имейл (след ръчен логин), трупа се:
node private/organizer-bot/organizer-bot.cjs cases --dirs "G:/път/DELO1,G:/път/DELO2" --out "G:/път/C" --email https://mail.google.com/mail/u/0/#inbox
```
`--stats <файл.md>` задава кой акумулиращ файл да ползва (иначе `C/organizer-cases.md`).

## Статистически файл
- `exact`/`similar`: `organizer-<функция>-<дата>.md` в `C` — всички премествания (оригинал → ново име).
- `cases`: `organizer-cases.md` (+ `.state.json`) в `C` — расте с всеки проверен имейл.

## Пътища (Windows)
Подавай пътищата във **Windows формат** (`G:/...` или `G:\...`), не MSYS `/tmp` — Node ги чете другояче.

## Зависимости
- `pdftotext` (PDF текст), `unzip` (docx), Playwright (картинков хеш) — вече налични в средата.
- Email-Bot: `../email-bot/email-bot.cjs` с нов режим `--case "<номер>"` (търси ВСИЧКА поща, не само изпратени;
  връща структурни данни: дата/час, кореспондент, пълно „относно", прикачени, етикети, инстанция от адресите
  rp_sofia/sgp/vkp@prb.bg; печата `CASE_RESULT={json}`). `--account <gmail-url>` превключва акаунт (/u/N/).

## Бележки / ограничения
- Имейлът се проверява по ЕДИН наведнъж (логваш се ръчно); находките се трупат в `organizer-cases.md`.
- Gmail търсенето е по номер на преписка/дело; виж пълните данни в стат файла и в отчета на Email-Bot.
- Прикачените се четат на ниво ред в списъка (best-effort); имената са достатъчни да се види кои молби ги няма на диска.
- Стар бинарен `.doc` се чете best-effort (само четими низове). `.docx` е пълно.
